# 06 构建与测试

## 环境

| 组件 | 版本 | 说明 |
|---|---|---|
| JDK | **21** | AGP 8.7 / Kotlin 2.0 不支持 JDK 25（会报 `IllegalArgumentException: 25.0.3`） |
| Android SDK | platform 35 + build-tools 35.0.0 | compileSdk / targetSdk 都是 35 |
| Gradle | 仓库自带 wrapper | Gradle 8.11 |
| 设备 | Android 7.0（API 24）起 | 跑仪器测试需要真机或模拟器 |

```bash
export JAVA_HOME=/path/to/jdk-21
export ANDROID_HOME=/path/to/android-sdk

./gradlew assembleDebug
# 产物：app/build/outputs/apk/debug/app-debug.apk
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

## 三个容易卡住的地方

1. **`gradle.properties` 里写了本机的 JDK 路径**：

   ```
   org.gradle.java.home=E:/Java/jdk-21.0.12.1+1
   ```

   换机器第一件事是把这行改成本机 JDK 21 的路径，或者直接删掉（改用 `JAVA_HOME`），
   否则会出现「明明装了 JDK 21 还是报找不到」这类错。

2. **`local.properties` 不入库**：`sdk.dir` 由 Android Studio 自动生成；命令行构建则靠 `ANDROID_HOME`。

3. **依赖下载走的是国内镜像**（aliyun / 腾讯云，见 `settings.gradle.kts`），
   `RepositoriesMode.PREFER_SETTINGS` 意味着构建脚本里再写 `repositories` 不生效。外网环境可自行删掉镜像行。

## Release 构建（R8）

`app/build.gradle.kts` 的 `release` 现在开着两项：

```kotlin
isMinifyEnabled = true       // R8：压缩 + 混淆
isShrinkResources = true     // 资源裁剪
proguardFiles(getDefaultProguardFile("proguard-android-optimize.txt"), "proguard-rules.pro")
```

`debug` 仍然 `isMinifyEnabled = false`（调试不混淆，方便断点与堆栈阅读）。

**keep 规则只有一条**（`app/proguard-rules.pro`），其余全部交给 R8 默认行为：

```proguard
-keepclassmembers class * {
    int computeVerticalScrollOffset();
    int computeVerticalScrollExtent();
    int computeVerticalScrollRange();
}
```

理由是项目里真正被反射按名访问的只有这三个方法：`InkOverlay` 用 `getDeclaredMethod` 取
View 的 protected 滚动进度方法，在 RecyclerView / NestedScrollView 实例上虚分派。
若被重命名或裁掉，分派会落回 View 的空实现，笔迹跟随滚动的偏移会算成 0。
其余依赖面很窄，**确认不需要 keep**：

* 无 `Class.forName`、无 `getIdentifier`、无 WebView JS 桥；
* 无 Gson / Moshi / Jackson / kotlin-reflect，JSON 走平台 `org.json`（非反射实现）；
* xlsx / docx 是自研零依赖读取器（不引 Apache POI），不存在按类名加载的解析器；
* ViewBinding 走 `findViewById`，模型类字段不需要保名；
* 布局里的自定义 View 由 LayoutInflater 反射构造，AGP 会按 aapt 结果**自动**生成 keep 规则
  （见 `seeds.txt` 里的 `InkOverlay` 构造），不需要手写。

另外保留 `SourceFile,LineNumberTable` 并用 `-renamesourcefileattribute SourceFile`，
release 崩溃栈能配合 mapping 定位，同时不泄露本地路径。

**产物与核对入口**（`assembleRelease` 后都在 `app/build/outputs/` 下）：

| 文件 | 用途 |
|---|---|
| `apk/release/app-release.apk` | 安装包（当前约 2.8 MB） |
| `mapping/release/mapping.txt` | 混淆映射：线上崩溃栈回溯用（约 17 MB，发版时留存） |
| `mapping/release/usage.txt` | R8 的 `-printusage` 结果：被裁掉的类 / 成员，核对「有没有误裁」 |
| `mapping/release/seeds.txt` | 被 keep 的入口（含 aapt 自动生成的自定义 View 规则） |
| `mapping/release/resources.txt` | 资源可达性：每条资源是否被 dex 引用到，核对 `shrinkResources` 有没有误删 |

```bash
./gradlew assembleRelease
# 产物：app/build/outputs/apk/release/app-release.apk
adb install -r app/build/outputs/apk/release/app-release.apk
```

**release 冒烟**：R8 改动后不能只看「编译通过」，要在模拟器 / 真机上把关键路径走一遍——
覆盖安装 → 导入示例（导入预览统计正常）→ 进答题页作答 → 开写画画一笔并退出写画
→ 交卷 → 成绩报告 → 记录列表；同时抓 logcat，确认没有
`FATAL EXCEPTION` / `ClassNotFoundException` / `NoSuchMethodError` / `NoSuchFieldError`。
`assembleRelease` 只验证「能打出来」，混淆后的运行期问题（反射类被裁、字段被改名）只有冒烟能发现。

**已知边界**（如实记录，改动前先看）：

1. 自定义 View 的 keep 依赖 aapt 自动规则：目前成立（seeds 已核对）。以后若新增
   **按类名反射构造**的 View、或按名字恢复 Fragment / ViewModel，必须补对应 keep，否则运行期找不到类。
2. `shrinkResources` 只保证「XML / dex 静态引用到的资源」可达；项目里没有用字符串拼资源名
   （`getIdentifier`），所以安全。以后若引入动态资源名查找，会被裁掉。
3. release 目前回退 debug 签名（见下节「签名」）；这与 R8 无关，只是内部试用包的安装与升级口径。

## CI（GitHub Actions）

两个工作流，都在 `.github/workflows/` 下：

| 工作流 | 触发 | 干什么 | 产物 |
|---|---|---|---|
| `ci.yml` | 推送 `main`、合入 `main` 的 PR、手动 | `assembleDebug` | Actions 里可下载 `qbank-debug-<sha>` 里的 APK，留 14 天 |
| `release.yml` | 推送 `v*` tag、手动指定 tag | `assembleRelease` → 建 GitHub Release | Release 附件：`qbank-<版本>.apk` + `SHA256SUMS.txt` |

发版的常规动作就是打个 tag：

```bash
git tag v1.0.1 && git push origin v1.0.1
```

**版本号**：tag 名去掉 `v` 作为 `versionName`（`v1.0.1` → `1.0.1`），`versionCode` 取该工作流的运行序号（单调递增，能正常覆盖安装）。
本地构建不带参数时仍用 `app/build.gradle.kts` 里的默认值，也可以用 `-PversionName=1.2.3 -PversionCode=42` 覆盖。

**签名**：`release` 构建按下面的顺序找密钥，都找不到就用 debug 签名（产物依然能直接安装，适合内部试用）：

1. 仓库 Secrets（推荐，配好即可产出正式签名包）
   - `QBANK_KEYSTORE_BASE64`：`base64 -w0 your.jks` 的结果
   - `QBANK_KEYSTORE_PASSWORD`、`QBANK_KEY_ALIAS`、`QBANK_KEY_PASSWORD`
2. 本地 `keystore.properties`（已在 `.gitignore` 里，字段 `storeFile` / `storePassword` / `keyAlias` / `keyPassword`）

配了正式密钥后请注意：debug 签名的包与正式签名的包签名不同，**换签名要卸载重装**。

CI 里有两处对仓库现状的兜底，本地构建时也可以照做：

- 删掉 `gradle.properties` 里的 `org.gradle.java.home`（作者本机路径），改由 `JAVA_HOME` 决定；
- `chmod +x gradlew`（Windows 上提交的文件容易丢可执行位）。

仪器测试（`connectedDebugAndroidTest`）需要模拟器，比较慢，没有放进 CI，本地或专门的设备上跑。

备份相关的用例在 `BackupArchiveTest.kt`：只验「打包 → 解包 → 校验」，
**不会动测试机上的真实试卷数据**（`BackupArchive.install` 会整库替换，故意没放进自动化）。

```bash
./gradlew :app:connectedDebugAndroidTest -Pandroid.testInstrumentationRunnerArguments.class=com.lytree.qbank.BackupArchiveTest
```

## 改东西时的自检顺序

1. 改了导入器 → 跑 `connectedDebugAndroidTest`，再手动导一次 App 内置示例（xlsx / 试卷包）；
2. 改了模板 / 生成脚本 → `node templates/make_templates.js`，脚本末尾会回读校验；
3. 改了示例 → `node tools/make_samples.js` 重新生成内置示例（xlsx / zip）；
4. 改了配色或尺寸 → 只动 `colors.xml` / `dimens.xml` 的 `fb_*` 令牌，页面里不要硬编码颜色。
