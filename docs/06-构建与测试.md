# 06 构建与测试

## 环境

| 组件 | 版本 | 说明 |
|---|---|---|
| JDK | **17** | AGP 8.7 / Kotlin 编译器不支持 JDK 21+（会报 `IllegalArgumentException`） |
| Android SDK | platform 35 + build-tools 35.0.0 | compileSdk / targetSdk 都是 35 |
| Gradle | 仓库自带 wrapper | Gradle 8.11 |
| 设备 | Android 7.0（API 24）起 | 跑仪器测试需要真机或模拟器 |

```bash
export JAVA_HOME=/path/to/jdk-17
export ANDROID_HOME=/path/to/android-sdk

./gradlew assembleDebug
# 产物：app/build/outputs/apk/debug/app-debug.apk
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

## 三个容易卡住的地方

1. **`gradle.properties` 里写了本机的 JDK 路径**：

   ```
   org.gradle.java.home=E:/Java/jdk-17.0.2
   ```

   换机器第一件事是把这行改成本机 JDK 17 的路径，或者直接删掉（改用 `JAVA_HOME`），
   否则会出现「明明装了 JDK 17 还是报找不到」这类错。

2. **`local.properties` 不入库**：`sdk.dir` 由 Android Studio 自动生成；命令行构建则靠 `ANDROID_HOME`。

3. **依赖下载走的是国内镜像**（aliyun / 腾讯云，见 `settings.gradle.kts`），
   `RepositoriesMode.PREFER_SETTINGS` 意味着构建脚本里再写 `repositories` 不生效。外网环境可自行删掉镜像行。

| 用例 | 覆盖点 |

## CI（GitHub Actions）

两个工作流，都在 `.github/workflows/` 下：

| 工作流 | 触发 | 干什么 | 产物 |
|---|---|---|---|
| `ci.yml` | 推送 `main`、合入 `main` 的 PR、手动 | `assembleDebug` | Actions 里可下载 `qbank-debug-<sha>` 里的 APK，留 14 天 |
| `release.yml` | 推送 `v*` tag、手动指定 tag | `assembleRelease` → 建 GitHub Release | Release 附件：`qbank-<版本>.apk` + `SHA256SUMS.txt` |

发版的常规动作就是打个 tag：

```bash
git tag v1.0.1 && git push origin v1.0.1
```

**版本号**：tag 名去掉 `v` 作为 `versionName`（`v1.0.1` → `1.0.1`），`versionCode` 取该工作流的运行序号（单调递增，能正常覆盖安装）。
本地构建不带参数时仍用 `app/build.gradle.kts` 里的默认值，也可以用 `-PversionName=1.2.3 -PversionCode=42` 覆盖。

**签名**：`release` 构建按下面的顺序找密钥，都找不到就用 debug 签名（产物依然能直接安装，适合内部试用）：

1. 仓库 Secrets（推荐，配好即可产出正式签名包）
   - `QBANK_KEYSTORE_BASE64`：`base64 -w0 your.jks` 的结果
   - `QBANK_KEYSTORE_PASSWORD`、`QBANK_KEY_ALIAS`、`QBANK_KEY_PASSWORD`
2. 本地 `keystore.properties`（已在 `.gitignore` 里，字段 `storeFile` / `storePassword` / `keyAlias` / `keyPassword`）

配了正式密钥后请注意：debug 签名的包与正式签名的包签名不同，**换签名要卸载重装**。

CI 里有两处对仓库现状的兜底，本地构建时也可以照做：

- 删掉 `gradle.properties` 里的 `org.gradle.java.home`（作者本机路径），改由 `JAVA_HOME` 决定；
- `chmod +x gradlew`（Windows 上提交的文件容易丢可执行位）。

仪器测试（`connectedDebugAndroidTest`）需要模拟器，比较慢，没有放进 CI，本地或专门的设备上跑。

## 改东西时的自检顺序

1. 改了导入器 → 跑 `connectedDebugAndroidTest`，再手动导一次 `sample/` 里的四种格式；
2. 改了模板 / 生成脚本 → `node templates/make_templates.js`，脚本末尾会回读校验；
3. 改了示例题库 → `node sample/make_xlsx.js` 重新生成 CSV / TXT / XLSX；
4. 改了配色或尺寸 → 只动 `colors.xml` / `dimens.xml` 的 `fb_*` 令牌，页面里不要硬编码颜色。
