## 导入链路

```
ImportActivity
  ├─ 本地文件：ContentResolver 读字节 / 题库包 zip
  ├─ 链接导入：UrlDownloader.download(url)     # http/https、跟随跳转、Content-Disposition 取文件名
  └─ Importer.detect(fileName, bytes)          # 扩展名 → magic → 文本特征
       ├─ ZIP  → QbankPackage.open()           # 解压、找主数据、图片落盘
       └─ JSON / CSV / XLSX / TXT
              └─ Importer.build()
                   ├─ 对应 parser → List<RawQuestion>（+ ImportIssue）
                   ├─ Normalizer.toQuestion()  # 题型/答案/分值/难度归一化 + 校验
                   └─ ImportOutcome(questions, issues, total, imported)
  └─ 预览页：勾选 → QBankDb.importAsPaper()    # 一个文件 = 一份试卷
```

要点：

* **链接导入只是换了一种拿字节的方式**：下载完仍走同一个 `detect → build → 预览`，不另做一套解析；
  单文件上限 64MB，链接拿不到扩展名时按内容探测结果补上；
* **parser 只负责「把文件读成 RawQuestion」**，字段映射（别名）在 `Normalizer`，校验结果也统一由它产出，
  所以四种格式的错误提示口径一致；
* `XLSX` 内部会把单元格拼成 CSV 再走 `CsvImporter`，因此表头规则完全同源；
* 题库包在 `Importer.build()` 里单独一条分支：解压 → 解析主数据 → `rewriteAssets()` 把相对路径换成绝对路径，
  入库前就换完，之后翻题不必再算包内位置。

## 卷面结构（PaperStructure）

`data/model/PaperStructure.kt` 把「一题一行的平铺列表」一次算成三级结构，其余界面只消费不重算：

```
试卷
└── Section（大类题型）：连续相同 subject，名称按 · - / 取最后一段
    └── Group（材料组）：大类内连续相同 material；无材料的题各自成组
        └── Question（题号 = 卷面顺序 1..N，组内不重编）
```

* `QuestionPagerAdapter`：大类首页一页说明页（name 非空才插），其后**每个材料组一页**——
  单题模式的答题内容以材料为准划分；`pageOfQuestion` / `questionOfPage` / `questionsOfPage` 口径不变。
* `QuestionListAdapter`：`isGroupStart()` 决定材料是否重复渲染，`isSectionStart()` 决定说明卡挂哪一题。
* `ExamActivity`：答题卡分组（`groupLabels`）与「弹出材料」的组定位都走结构；补答案重读整卷后
  `rebuildStructure()` 重建并下发给两个适配器（`updateStructure`）。
* `SplitExamActivity`：按材料文本在 `groups` 里找**所属的那一组**（跨大类的同名材料不会并组），
  右栏题号偏移取 `group.startIndex`。
* `ModuleHeaders` 只剩「把 Section 翻译成说明卡」：标题 `名称 (N题)` + 作答说明文案。

结构纯派生、不落库：作答 / 笔记 / 进度都按 `question.id` 存；笔迹按「作答记录 + 目标（题目 / 材料）」存，
与卷面结构无关，旧数据无需迁移。

## 数据库（11 张表）

| 表 | 内容 |
|---|---|
| `banks` | 题库（名称 / 描述 / 科目） |
| `words` | 词库（词条 / 拼音 / 首字母 / 分类 / 细分 / 释义 / 例句 / 出处），v4 新增 |
| `questions` | 题目全字段，含材料、选项、答案、解析等 |
| `papers` | 试卷（名称 / 限时 / 模式） |
| `paper_questions` | 试卷与题目的顺序关系 |
| `records` | 一次作答（得分 / 满分 / 用时 / 完成时间 / 本次标记的题）；`submitted_at = 0` 是答题草稿，不进记录列表 |
| `record_answers` | 逐题作答与判分结果（补答案后用它重判） |
| `record_inks` | 遮盖层笔迹，v7 新增：按 `(record_id, kind, target_id)` 存，kind = question / material，材料用组首题 id |
| `settings` | 键值配置（判题规则、浏览模式、背诵掌握 / 重点 / 字号等） |
| `inks` | v1/v2 的按题全局笔迹（旧表，v7 起不再读写，保留数据不删） |
| `notes` | 按题的笔记 |

v8 起 `records` 多一列 `marked`（逗号分隔的题 id，与 `exam_progress.marked` 同一种编码）：
答题过程中标记仍写在进度表里（退出可续做），**交卷时随本次作答一并落库**，旧库由 `onUpgrade` 补列，
旧记录读出来是空集（等价于「那次没标记」）。报告页按它给逐题卡挂「已标记」标签，记录列表显示标记题数。

## 判题

`engine/Judge.kt` 是唯一的判分入口：单选完全一致、多选全对才得分（可配少选给分）、
不定项错选 0 分 / 少选 50%、判断归一化后比对、填空逐空比对、主观按得分点命中率。

`QBankDb.rejudgeRecord()` 用 `record_answers` 里保存的原始作答重新调 `Judge`，
所以补答案后不需要用户重做，成绩报告直接刷新。

## 加一个字段要改哪儿

1. `Normalizer.Field` + `FieldAliases`（表头别名）；
2. `RawQuestion` 取值处 → `Normalizer.toQuestion()`；
3. `Question` 模型 + `QBankDb` 建表/读写（含 `onUpgrade`）；
4. `JsonImporter` 的字段循环（JSON 侧）；
5. 需要展示的话再动 `QuestionCardBinder` / `ReportActivity`。
