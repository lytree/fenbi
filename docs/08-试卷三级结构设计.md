# 08 · 试卷三级结构设计：大类题型 → 材料 → 题目

> 状态：**已实施**（2026-10-24；第 9 节三个决策点按推荐项落地：全卷连续题号 / 同材料不连续各自成组 / subject 为空不兜底）
> 目标读者：实施本次改造的人；阅读前建议先看 [07 代码结构](07-代码结构.md)。

---

## 1. 目标

把卷面从「平铺题列表 + 各界面各自聚合」升级为统一的**三级结构**：

```
试卷
└── 大类题型（资料分析 / 言语理解 / 常识判断 …）
    └── 材料（一则材料，含表格 / 配图 / 图表）
        └── 题目（全卷连续编号 1,2,3,…,N）
```

- **题目按照卷面顺序连续编号 1,2,3,4,5…**（全卷唯一，不按材料组重编）；
- **单题模式的答题内容以材料为准分页**：一则材料 + 它带的全部小题 = 一页。

### 现状问题

「大类」和「材料组」目前是**渲染时临时推导**的概念，同一套判据复制在四处：

| 位置 | 各自做的事 |
|---|---|
| `QuestionPagerAdapter.buildPages()` / `materialGroupEnd()` | 单题模式：按 subject 插说明页 + 按连续同材料合页 |
| `QuestionListAdapter.sameMaterialAsPrevious()` | 多题模式：判断材料是否已在上一题渲染 |
| `ModuleHeaders` | 按连续相同 subject 划模块、算模块题量 |
| `ExamActivity.groupLabels()` | 答题卡：按 subject 拼分组标签 |

判据重复意味着口径容易漂移（改一处漏三处）；「组」没有统一实体，分屏、答题卡、说明卡都在各自拼装。

## 2. 结构模型

新增 `data/model/PaperStructure.kt`——**一次构建，处处消费**：

```kotlin
/**
 * 试卷三级结构：大类 → 材料 → 题目。
 * 由按 paper_questions 顺序的题目列表派生，纯内存对象，不落库。
 */
class PaperStructure(questions: List<Question>) {

    /** 大类（模块）。name=null 表示「未分类」段（subject 为空），不渲染说明卡 */
    class Section(val name: String?, val groups: List<Group>)

    /** 材料组：一则材料（以首题代表，含配图/图表渲染所需全部字段）+ 连续小题 */
    class Group(val material: Question, val questions: List<Question>) {
        /** 是否真的带材料（false = 无材料的单题组） */
        val isMaterialGroup: Boolean get() = material.material.isNotBlank()
    }

    /** 大类列表（卷面顺序） */
    val sections: List<Section>

    /** 全卷平铺的材料组（卷面顺序），供单题分页 / 分屏直接索引 */
    val groups: List<Group>

    /** 题号(0-based) → 组号 */
    val groupOfQuestion: IntArray

    /** 题号(0-based) → 大类序号 */
    val sectionOfQuestion: IntArray
}
```

**构建时机**：`ExamActivity` / `SplitExamActivity` 加载 `questions` 后构建一次，传给两个适配器、答题卡与分屏。题目集合在答题过程中不变，结构无需重建。

## 3. 划分规则（单趟扫描，O(n)）

输入：按 `paper_questions` 顺序的题目列表。

1. **大类**：连续且 `moduleName(q)` 相同的题归入同一 `Section`（命名归一沿用 `ModuleHeaders.moduleName`：`行测·资料分析` → `资料分析`）；subject 全空的卷归入一个 `name=null` 的 Section。
2. **材料**：Section 内**连续**、`trim()` 后 `material` 全文相等的题归入同一 `Group`；material 为空的题单独成组。
3. **大类边界优先于材料**：同一材料文本跨 Section 时在边界断开成两组（维持现状——保证大类说明页不会被卷进材料组页）。

**判据口径**：材料以 trim 后**全文相等**为准（现状口径，不引入相似度/前缀匹配）。

### 边界情况

| 场景 | 处理 |
|---|---|
| subject 为空（大多数手打试题） | 归入 name=null 的 Section，**不出说明卡**，材料照常聚组（维持现状） |
| 同一材料文本在卷面**不连续**（中间插了别的题） | **尊重卷面顺序，各自成组**；导入校验新增 warning：建议按「大类→材料→题目」顺序编写 |
| 材料相同但 subject 不同 | 在大类边界断开，两段各成一组 |
| 组内只有 1 题且带材料 | 正常组，材料照常展示（弹材料/分屏照常用） |
| 空卷 | sections / groups 为空，`pageOfQuestion` 等沿用现有兜底（回 0 不越界） |

---

## 4. 题号规则（固定口径）

- **题号 = 该题在试卷中的顺序（1..N，全卷连续）**。材料组页里的小题显示各自的整卷题号（如 `86. 87. 88.`），**不按组内重编**成 1,2,3。
- 答题卡、补答案（`1.A 2.B` 题号匹配）、成绩报告、错题重练统一使用**整卷题号**——补答案的批量粘贴才有唯一落点。
- 现状 `QuestionCardBinder` 的 `tvIndex = position + 1` 已是该口径，本设计将其**固化为规范**，任何界面不得另行编号。

---

## 5. 单题模式分页（以材料为准）

页表生成改为消费 `PaperStructure`：

- 每个 `name != null` 的 Section 起始处插一页**大类说明页**（现有 `view_module_header` 样式，标题如「资料分析 (20题)」+ 说明文案）；
- **每个 Group 一页**：
  - 材料组页 = 材料渲染**一次**（多题组用上下分栏：材料固定上区，小题放底部悬浮面板，中间手柄拖动调占比；单题组随卡滚动）；
  - 普通组 = 一题一页（现状）；
- `pageOfQuestion / questionOfPage / questionsOfPage / isModuleIntroPage` 保持现有签名，`ExamActivity` 的调用点（答题卡跳转、自动下一题、模式切换双向定位、单卡刷新）**无需改动**。

## 6. 多题模式与其它界面的消费

| 界面 | 改为 |
|---|---|
| 多题列表 `QuestionListAdapter` | `sameMaterialAsPrevious` → `groupOfQuestion` 比较（同组且非首题 → 隐藏材料）；说明卡在 Section 首题渲染一次 |
| 答题卡 | 分组标签从 `groupLabels()` 即时拼装 → sections 顺序 + 各 Section 的题号区间 |
| 左右分屏 `SplitExamActivity` | 左栏取一个 `Group` 的 material，右栏 `Group.questions` + `indexOffset = 组首题号`（替换现在的按材料文本查找） |
| 成绩报告·分模块正确率 | 数据源换 sections（聚合口径不变） |
| 模块说明卡 `ModuleHeaders` | 只保留 `moduleName` / `descOf`（命名归一与说明文案），划分职责整体移交 `PaperStructure` |

## 8. 测试用例

1. 单一大类 + 3 组材料（每组 5 题）→ 单题模式 = 1 页说明页 + 3 页组页；题号 1..15 连续；
2. subject 为空的全卷 → 无说明页，材料组照常聚组；
3. 同一材料跨大类 → 断成两组，各带说明页；
4. 同一材料不连续 → 两组，卷面顺序不变；
5. 单题带材料（**一材料一题**）→ 单题页照常显示材料，但**不出「弹出材料」入口**（多题模式的列表卡同理）；**一材料多题** → 列表组首卡 / 单题模式组页材料头都有入口，两处都走 `showMaterialPopup`；
6. `showMaterialPopup` 对「组题量 < 2」的调用直接返回，不弹浮层、不进分屏（按钮隐藏之外的兜底）；
7. 单题 ↔ 多题模式切换双向定位回归（组页 ↔ 列表）；
8. 答题卡分组区间与 sections 逐段一致；补答案按整卷题号匹配不变。

## 12. 分模块答题：每个层级都能当成一张卷（v0.0.32）

有了三级结构，「一份卷」不再是答题的最小单位：**整卷 / 一个大类 / 一则材料**都能单独当一张卷做。
比如一套行测卷，资料分析、数量关系、言语理解可以分开刷，各出一份成绩、各留一份进度。

### 12.1 范围怎么表达（`ExamScope`）

```kotlin
data class ExamScope(val anchorQuestionId: Long = 0L, val material: Boolean = false)
```

| 范围 | 落库 key | 切题 |
|---|---|---|
| 整卷 | 空串 | `structure.questions` |
| 一个大类 | `s:<首题 id>` | 该 `Section.questions` |
| 一则材料 | `m:<组首题 id>` | 该 `Group.questions` |

* 锚点用**题目 id**，不用大类名：名字是 `subject` 归一出来的，改名 / 重新导入会变，题目 id 稳定；
* 材料组被改动（锚点题没了）→ 退到该题所在大类 → 再退整卷，**不会给出一张空卷**；
* 展示标题（`label()`）不落库，每次进卷按当前结构现算：「资料分析」「资料分析 · 材料2」；
* 题号在范围内从 1 重排（模块练习按 1..N 数更顺），答题卡、判分、报告都只看这一截。

### 12.2 数据侧：记录与进度按范围分桶（DB v13）

如果不分桶，进「资料分析模块」会抢走整卷那条 `ongoing` 草稿和那份未交卷进度——两边互相覆盖。

| 位置 | 改动 |
|---|---|
| `records` | 新增 `scope TEXT DEFAULT ''`（空串 = 整卷，老记录就是这个口径）；`ensureDraftRecord` / `abandonDraftRecords` / `discardDraftRecords` 都按 `(paper_id, scope)` 找草稿 |
| `exam_progress` | 主键 `paper_id` → `(paper_id, scope)`，重建表；老数据按空串搬过去，升级后整卷进度照旧能续做 |
| `finishSubmission` | 只清 `(paper_id, scope)` 这一份进度，交整卷不会顺手抹掉模块进度 |
| `ExamRecord` / `ExamProgress` | 带上 `scope`：记录列表点回来续做时按同一个范围进卷 |

限时卷按题量折算时长（`scaledDuration`）：整卷 120 分钟、做 20/135 题给约 18 分钟，
否则一进模块就顶着一张两小时的倒计时。

### 12.3 界面：首页四级树（`PaperListFragment` + `PaperTreeAdapter`）

没有单独的「试卷目录」页——**层级直接摊在首页的树上**，点哪一层就做哪一层：

```
2024国考行测             6 份 · 240 题   [整组作答]     ← 整组合成一张卷
  资料分析               30 题  ›                     ← 整卷作答
    资料分析             20 题  ›                     ← 只做这个大类
      材料1               5 题                         ← 只做这一则材料
  言语理解               30 题
```

* 整张试卷卡 = 整卷开练；行尾箭头只管**展开层级**（材料只列真的带材料的组，单题组本来就是一题）；
* 层级**懒加载**：展开某份卷时才读这份卷的题目、建 `PaperStructure`，展开过一次就缓存；
  展开状态（哪几份卷、哪几个大类）与折叠的组一起存本地，重进 App 还是原样；
* 首页不再为层级查库：折叠 / 展开只重排节点。

答题页 `importAnswers` 仍按**整卷**题目匹配答案文件：答案表的题号是整卷题号，
拿模块那一截去对会把「第 21 题」套到模块第 1 题上。

### 12.4 最顶层级：整组作答（虚拟卷 id，v0.0.33）

组里各份卷本来就是同一套卷拆开的工作表，所以最顶上的**导入组也要能直接按试卷形式作答**——
组标题上的「整组作答」把整组合成一张卷（组里只剩一份卷时点的就是那份卷本身，不另起虚拟卷）。

组不是库里的一行 `papers`，但记录 / 进度 / 报告只认一个 `paper_id`，于是给组造一个**虚拟卷 id**：

```kotlin
object PaperRef {
    fun groupPaperId(setId: Long): Long = if (setId > 0) -setId else 0  // 0 = 无效
    fun setIdOf(paperId: Long): Long = if (paperId < 0) -paperId else 0
}
```

* `QBankDb.getGroupPaper(setId)` 现拼一张卷：题目按组内各卷的建卷顺序（`papers.id`）首尾相接，
  时长按各卷累加，卷名取组标题；**同一道题重复出现（错题重练复用原卷题目行）按题目 id 去重**，
  否则作答 / 题号 / 每题用时按 id 存的那套会被搅乱；
* `QBankDb.getPaperOrGroup(id)` 是唯一读卷入口：正数读卷、负数读组；答题页 / 分屏页 / 报告 /
  补答案 / 补录 / 记录续做都走它，**数据库表结构一行没改**（`records.paper_id`、
  `exam_progress(paper_id, scope)` 天然分桶）；
* 组被删（或组里卷删光）时 `deleteGroupRecords()` 一并清掉 `paper_id = -组 id` 的记录与进度，
  记录列表里不会留一条点不开的「整组练习」；
* 「未分组」是兜底伪组（没有 `paper_sets` 行），不给整组作答入口。
