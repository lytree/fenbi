# 09 词库（成语 + 实词）

词库是跟题库**并行**的一套数据：题库用来做题判分，词库用来背词。两者不共用表、不互相影响，
删题库不会动词库，反之亦然。

## 一、这次改了什么

| | 以前 | 现在 |
|---|---|---|
| 收什么词 | 只收四字成语，其余丢掉 | **成语 + 实词一起收**，不再按字数一刀切 |
| 分类 | 无 | 每条带分类（成语 / 实词 / 其他）+ 可选细分（名词、动词、褒义…） |
| 排序 | — | **一律按拼音首字母**分组（A→Z，取不到归 `#`），组内按全拼、再按词条排 |
| 拼音 | 要人填 | 表里有就用（自动去声调），没有就按内置 2.7 万字表逐字拼 |
| 数据来源 | — | 直接导入**文档**：Word(.docx) / Excel(.xlsx) / CSV / TXT / JSON |

## 二、导什么文件

导入页（词库 Tab → 右上角「导入」→ 选择文档）认这几种：

| 格式 | 怎么读 |
|---|---|
| `.docx` | 解 `word/document.xml`，优先取「表头能认出词条列」的那张表；一个表都没有时，按「一段一个词条」解析 |
| `.xlsx` | 取第一个有数据的 sheet，拼成表格后与 CSV 同一套规则 |
| `.csv` | 自动识别分隔符（`,` `;` Tab `\|`）与编码（UTF-8 / GBK） |
| `.txt` | 一行一个词条，Tab / `\|` / 连续空格分列；首行像表头时自动改走表格解析 |
| `.json` | `[{"词条": "...", "拼音": "...", ...}]` 或 `{"words": [...]}` |

> 老版 `.doc`（二进制）读不了，会直接提示另存为 `.docx`。

### 表格写法（推荐）

第一行是表头，一行一个词条：

| 词条 | 拼音 | 分类 | 细分 | 释义 | 例句 | 出处 |
|---|---|---|---|---|---|---|
| 画蛇添足 | huà shé tiān zú | 成语 | 贬义 | 比喻做了多余的事，反而不合适。 | 再加一段纯属画蛇添足。 | 战国策·齐策二 |
| 徜徉 | cháng yáng | 实词 | 动词 | 安闲自在地步行。 | 午后徜徉在林荫道上。 | |

**只有「词条」列是必须的**，其余都能省。表头别名（`词条` / `词语` / `成语` / `实词` / `word` …）见
`WordAliases`，全半角、空格、括号会先归一化再比对。

### 没有表头也能导

首行认不出词条列时，按列序兜底：第 1 列词条；第 2 列如果整列长得像拼音（纯字母）就记拼音，否则记释义；
后面依次是释义、例句、出处。这种情况会在解析提示里标一条警告。

## 三、分类怎么定

1. **有「分类」列** → 按列里的值：`成语` / `四字成语` / `idiom` → 成语；`实词` / `词语` / `word` → 实词；认不出的按第 2 步兜底。
2. **没有分类列** → 按字数推测：**4 个字记「成语」，其余记「实词」**。

推测不是静默的：导入页顶部会用橙色标出「有 N 条分类是推测的」，预览里每条都能看到自己的分类标签，
确认前可以关掉不想要的。**推测只影响分类标签，不会丢词。**

> 为什么是字数：离线环境下判断一个四字串是不是成语需要一部成语词典，体积不值当。
> 4 字串里确实有「社会主义」这类非成语，遇到就在源表里补一列「分类」覆盖掉。

## 四、什么会被丢掉

只丢三类，且每条都会在解析提示里给出**行号 + 原因**：

| 情况 | 提示 |
|---|---|
| 词条为空 | 词条为空，已跳过 |
| 不含汉字（纯英文 / 数字 / 符号） | 「xxx」不含汉字，不是成语或实词，已跳过 |
| 超过 16 个字 | 「xxx…」有 N 个字，像是整句，已跳过 |

重复词条按**首次出现**保留，其余合并，最后汇总一条 INFO。

## 五、拼音与排序

* 拼音来源优先级：表里的「拼音」列 → 内置字表逐字拼。
* 表里的拼音会自动去声调、`ü` 记作 `v`，`huà shé tiān zú` 和 `huashetianzu` 都能用。
* 逐字拼用的是每个字的**常用读音**（多音字取第一个），所以 `行` 一律拼 `xing`；
  在意多音字就在源表里写「拼音」列。
* 首字母 = 拼音第一个字母大写，取不到记 `#`。
* 排序口径固定为 `initial → 全拼 → 词条`，入库时就写进索引字段，列表页不再二次计算：

```sql
CREATE INDEX idx_word_sort ON words(initial, pinyin);
SELECT * FROM words ORDER BY initial, pinyin, text;
```

## 六、重复导入

* 默认**按词条合并**：同名词条更新释义 / 分类 / 拼音，不会产生重复行。
* 勾上「覆盖整个词库」→ 先清空再写，适合整表换版本。

## 七、界面

* 底部导航「词库」Tab：分类胶囊（全部 / 成语 / 实词）+ 按首字母分组的列表 + 右侧 A-Z 索引条（点一下跳组）。
* 词条行显示：词条、拼音、分类·细分、2 行释义；点一下展开完整释义与例句 / 出处。
* 空态直接给「导入词表」按钮。

## 八、示例

导入页「载入示例词表」有两份内置样例：

* `samples/词库示例.csv` —— 12 条，成语与实词混排，带分类 / 细分 / 例句 / 出处；
* `samples/词库示例.docx` —— 同样格式的 Word 表格，其中一条故意没填分类，用来演示推测逻辑。

## 九、代码位置

| 文件 | 职责 |
|---|---|
| `data/model/Word.kt` | 词条模型 + 分类枚举 |
| `data/importer/WordImporter.kt` | 文档 → 词条：格式分发、表头别名、分类判定、拼音、排序 |
| `data/importer/DocxReader.kt` | 零依赖 DOCX 读取（表格 + 段落） |
| `data/importer/PinyinTable.kt` | 内置拼音表（`assets/pinyin.txt`）的加载与归一化 |
| `data/db/QBankDb.kt` | `words` 表（v4 新增）、upsert、按分类查询 |
| `ui/word/WordListFragment.kt` | 词库列表、分类筛选、字母索引 |
| `ui/word/WordAdapter.kt` | 分组 + 展开 |
| `ui/word/WordImportActivity.kt` | 选文档 → 预览 → 导入 |

拼音表由 `tools/gen_pinyin.py` 从 [pinyin-data](https://github.com/mozillazg/pinyin-data) 生成（v0.15.0，2.7 万字），
换数据源时重跑脚本即可，不要去手改 `assets/pinyin.txt`。
