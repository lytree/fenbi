# 09 词库（成语 + 实词）

词库是跟试卷**并行**的一套数据：试卷用来做题判分，词库用来背词。两者不共用表、不互相影响，
删试卷不会动词库，反之亦然。

入口在底部导航「背诵」Tab 的第一段（顶部切换条：词库 / 政治 / 常识）。

## 一、这次改了什么

| | 以前 | 现在 |
|---|---|---|
| 收什么词 | 只收四字成语，其余丢掉 | **成语 + 实词一起收**，不再按字数一刀切 |
| 分类 | 无 | 每条带分类（成语 / 实词 / 其他）+ 可选细分（名词、动词、褒义…） |
| 排序 | — | **一律按拼音首字母**分组（A→Z，取不到归 `#`），组内按全拼、再按词条排 |
| 拼音 | 要人填 | 表里有就用（自动去声调），没有就按内置 2.7 万字表逐字拼 |
| 数据来源 | — | 直接导入**文档**：Word(.docx) / Excel(.xlsx) / CSV / TXT / JSON |

## 二、导什么文件

导入页（底部「试卷」→ 右上角「导入」→ 卡片「导入词表」→ 选择文档）认这几种：

| 格式 | 怎么读 |
|---|---|
| `.docx` | 解 `word/document.xml`，优先取「表头能认出词条列」的那张表；一个表都没有时，按「一段一个词条」解析 |
| `.xlsx` | 取第一个有数据的 sheet，拼成表格后与 CSV 同一套规则 |
| `.csv` | 自动识别分隔符（`,` `;` Tab `\|`）与编码（UTF-8 / GBK） |
| `.txt` | 一行一个词条，Tab / `\|` / 连续空格分列；首行像表头时自动改走表格解析 |
| `.json` | `[{"词条": "...", "拼音": "...", ...}]` 或 `{"words": [...]}` |

> 老版 `.doc`（二进制）读不了，会直接提示另存为 `.docx`。

### 表格写法（推荐）

第一行是表头，一行一个词条：

| 词条 | 拼音 | 分类 | 细分 | 释义 | 例句 | 出处 |
|---|---|---|---|---|---|---|
| 画蛇添足 | huà shé tiān zú | 成语 | 贬义 | 比喻做了多余的事，反而不合适。 | 再加一段纯属画蛇添足。 | 战国策·齐策二 |
| 徜徉 | cháng yáng | 实词 | 动词 | 安闲自在地步行。 | 午后徜徉在林荫道上。 | |

**只有「词条」列是必须的**，其余都能省。表头别名（`词条` / `词语` / `成语` / `实词` / `word` …）见
`WordAliases`，全半角、空格、括号会先归一化再比对。

### 没有表头也能导

首行认不出词条列时，按列序兜底：第 1 列词条；第 2 列如果整列长得像拼音（纯字母）就记拼音，否则记释义；
后面依次是释义、例句、出处。这种情况会在解析提示里标一条警告。

## 三、分类怎么定

1. **有「分类」列** → 按列里的值：`成语` / `四字成语` / `idiom` → 成语；`实词` / `词语` / `word` → 实词；认不出的按第 2 步兜底。
2. **没有分类列** → 按字数推测：**4 个字记「成语」，其余记「实词」**。

推测不是静默的：导入页顶部会用橙色标出「有 N 条分类是推测的」，预览里每条都能看到自己的分类标签，
确认前可以关掉不想要的。**推测只影响分类标签，不会丢词。**

> 为什么是字数：离线环境下判断一个四字串是不是成语需要一部成语词典，体积不值当。
> 4 字串里确实有「社会主义」这类非成语，遇到就在源表里补一列「分类」覆盖掉。

## 四、什么会被丢掉

只丢三类，且每条都会在解析提示里给出**行号 + 原因**：

| 情况 | 提示 |
|---|---|
| 词条为空 | 词条为空，已跳过 |
| 不含汉字（纯英文 / 数字 / 符号） | 「xxx」不含汉字，不是成语或实词，已跳过 |
| 超过 16 个字 | 「xxx…」有 N 个字，像是整句，已跳过 |

重复词条按**首次出现**保留，其余合并，最后汇总一条 INFO。

## 五、拼音与排序

* 拼音来源优先级：表里的「拼音」列 → 内置字表逐字拼。
* 表里的拼音会自动去声调、`ü` 记作 `v`，`huà shé tiān zú` 和 `huashetianzu` 都能用。
* 逐字拼用的是每个字的**常用读音**（多音字取第一个），所以 `行` 一律拼 `xing`；
  在意多音字就在源表里写「拼音」列。
* 首字母 = 拼音第一个字母大写，取不到记 `#`。
* 排序口径固定为 `initial → 全拼 → 词条`，入库时就写进索引字段，列表页不再二次计算：

```sql
CREATE INDEX idx_word_sort ON words(initial, pinyin);
SELECT * FROM words ORDER BY initial, pinyin, text;
```

## 六、重复导入

* 默认**按词条合并**：同名词条更新释义 / 分类 / 拼音，不会产生重复行。
* 勾上「覆盖整个词库」→ 先清空再写，适合整表换版本。

## 七、界面

* 底部导航「背诵」Tab 的第一段就是词库（三段切换：词库 / 政治 / 常识，另外两段见 [11 背诵](11-背诵.md)）→ 词库页顶部是**搜索框** + 分类胶囊（全部 / 成语 / 实词 / 标签）+ 按首字母分组的列表 + 右侧 A-Z 索引条（点一下跳组）。
* 原「成语汇总」页已并进本页：搜索框就是它的那一个（词条 / 拼音 / 释义 / 标签都能命中，输入单个字母按首字母匹配），归类浏览由标签筛选承担，词典页本身已删除。
* 词条行显示：词条、拼音、分类·细分、2 行释义；点一下展开完整释义与例句 / 出处。
* 空态直接给「导入词表」按钮。

### 标签筛选

分类只有一个维度，细分标签（名词 / 动词 / 褒义 / 对比辨析 / 各语义分组…）是自由文本，
个数随词表来源浮动，所以不做固定筛选项，走**弹窗 + 搜索 + 多选**：

| 行为 | 说明 |
|---|---|
| 入口 | 分类胶囊右侧「标签」；选中后变成「标签 N」并高亮 |
| 弹窗 | 标题下写明当前范围（全部 / 成语 / 实词）和标签个数；列表每项是「勾选框 + 标签 + 条数」，条数多的在前，「未标注标签」永远垫底 |
| 搜索框 | 按标签文字过滤（`contains`，忽略大小写） |
| 多选口径 | 标签之间取**并集**，与分类取**交集**：`(tag 命中任一已选标签) AND category = ?` |
| 按段匹配 | 标签用 `·` 拼多段（`对比辨析·事情不顺利`）。筛「对比辨析」时四条 `LIKE` 一起上（全等 / 前缀 / 后缀 / 中缀），所以能命中所有带这一段的词 |
| 已选展示 | 胶囊行单独一行横滚，点单个「标签 ×」即时移除；点「清除筛选条件」全部复位 |
| 换分类 | 清空标签——标签清单本身按分类统计，留着旧标签多半一条都筛不出来 |
| 筛空 | 词库有词但筛选无结果时给「没有符合条件的词条 + 清除筛选条件」，不再是空白列表 |

标签统计在 `QBankDb.listWordTags()`：把每个词条的 tag 按 `·` 拆段累加计数，
所以「对比辨析」这种一级标签的条数包含它下面各分组的词，而不是只算裸标签那批。

**标签里不保留来源词表的分组编号。** 词表按「第一组 / 第二组 …」编排，
这些编号对使用者没意义，还会让标签列表变成一长串「第七组 动作」「第十组 事情不顺利」。
入库前统一由 `Word.stripGroup()` 去掉开头的「第 N 组」，只留后面的描述；
整段只有编号的直接丢弃（这种词条会落到「未标注标签」）。规则只作用于标签列，
释义和出处里出现的「组」不受影响。老库在 v6 升级时全表重写一遍 tag 列，
升级后与全新灌库的结果完全一致（当前内置词库 78 个标签段）。

## 八、内置词库（装上就有词）

App 自带一份正经词库，**首次打开词库页自动灌入**，不用先找文件导入。

| 项 | 值 |
|---|---|
| 资源 | `assets/builtin/words.csv`（约 437 KB，压缩后约 130 KB） |
| 条目 | **2201 条**：成语 1075 · 实词 1126 |
| 来源 | 《成语与实词汇总（合并版）》docx |
| 生成 | `dotnet run tools/BuildBuiltinWords.cs -- <源.docx> <输出.csv>` |

灌库逻辑在 `data/BuiltinWords.kt`：读 asset → 走的就是导入器那一套（`WordImporter.build`，
所以拼音、分类、排序口径跟手动导入完全一致）→ `upsertWords` → 打上 SharedPreferences 标记。
**只自动灌一次**：之后用户删词、整表覆盖都不会被偷偷塞回来；想重灌就进导入页选「内置词库」。

两千多条在主线程逐字算拼音会卡出 ANR，所以整段跑在名为 `builtin-words-seed` 的后台线程，
完成后再回主线程刷新列表。

### 源文档怎么变成这份 CSV

`tools/BuildBuiltinWords.cs` 直接解 `word/document.xml`，按文档结构取数：

| 源文档位置 | 取法 | 落成 |
|---|---|---|
| 子表一 · 成语汇总（H3 A–Z 分节） | 段落 `词条：释义〔分类标签〕` | 成语；`〔…〕` 记作细分 |
| 成语归类表（179 行） | `成语分类 / 子类 / 个数 / 成语` | 给正文里没标签的成语补细分 |
| 二、高频实词辨析（16 组） | `组 / 词语 / 释义 / 下册分组` | 实词；分组去掉「第 N 组」编号后记作细分 |
| 三、高频三字词（73 行） | `词语 / 释义 / 下册分组` | 实词，细分固定「三字词」 |
| 四、400 组 | `拼音 / 对比词组 / 释义 / 下册分组` | 按 `/` 拆成两条，释义写成「与「另一词」辨析：…」 |
| 五、下册独有（87 行） | `词语 / 下册分组` | 实词，无释义（源文档就没给） |

去重按词条文本合并：成语优先于实词，释义取更长的那条，细分用 `·` 拼接。
拼音一列**故意留空**——交给 App 的内置拼音表算，避免脚本里再维护一套多音字规则。

## 十、代码位置

| 文件 | 职责 |
|---|---|
| `data/model/Word.kt` | 词条模型 + 分类枚举 + 标签规范化（`normalizeTag` / `splitTags` / `stripGroup`） |
| `data/BuiltinWords.kt` | 内置词库 asset 的读取与首次灌库 |
| `data/importer/WordImporter.kt` | 文档 → 词条：格式分发、表头别名、分类判定、拼音、排序 |
| `data/importer/DocxReader.kt` | 零依赖 DOCX 读取（表格 + 段落） |
| `data/importer/PinyinTable.kt` | 内置拼音表（`assets/pinyin.txt`）的加载与归一化 |
| `data/db/QBankDb.kt` | `words` 表（v4 新增；v5 清重复标签 + 补索引；v6 去「第 N 组」前缀）、upsert、按分类 / 标签 / 关键词查询 |
| `ui/word/WordListFragment.kt` | 词库列表、搜索、分类 + 标签筛选、字母索引 |
| `ui/word/WordTagDialog.kt` | 标签多选弹窗（搜索 + 计数 + 清空） |
| `ui/word/WordAdapter.kt` | 分组 + 展开 |
| `ui/word/WordImportActivity.kt` | 选文档 → 预览 → 导入 |

内置词库由 `tools/BuildBuiltinWords.cs` 从源 docx 生成，改了源文档就重跑脚本，不要手改
`assets/builtin/words.csv`。

拼音表由 `tools/GenPinyin.cs` 从 [pinyin-data](https://github.com/mozillazg/pinyin-data) 生成（v0.15.0，2.7 万字），
换数据源时重跑脚本即可，不要去手改 `assets/pinyin.txt`。

### 两个 tools 脚本

`tools/` 下都是 .NET 10 的 **file-based app**：单个 `.cs` 文件、没有 `.csproj`、不引第三方包
（docx 就是个 zip，`System.IO.Compression` + `System.Xml.Linq` 足够），
需要 .NET 10 SDK，直接 `dotnet run` 跑，产物写回仓库里的资产文件：

```bash
# 内置词库：源 docx → assets/builtin/words.csv
dotnet run tools/BuildBuiltinWords.cs -- "成语与实词汇总（合并版）.docx" app/src/main/assets/builtin/words.csv

# 拼音表：pinyin-data 的 pinyin.txt → assets/pinyin.txt
dotnet run tools/GenPinyin.cs -- pinyin_full.txt app/src/main/assets/pinyin.txt
```

两个脚本都能在源文件被 Word 打开时读取（`FileShare.ReadWrite`），输出统一 UTF-8 无 BOM + LF，
和仓库 `.gitattributes` 的 `eol=lf` 对齐，避免「本地编的包」和「CI 编的包」内容不一致。
