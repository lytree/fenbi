# 10 备份与恢复

设置页 → 「备份与恢复」。整库打包成一个 zip，可以留在手机里、分享进任何网盘。备份包不出本机——App 不上传任何地方。

## 备份包里是什么

```
qbank-backup-20261029-2230.zip
├── manifest.json     # 包标记 / 创建时间 / 库版本 / 条数 / 体积 / db 的 MD5
├── qbank.db          # 试卷、题目、作答记录、笔迹、笔记、判题规则（整库一份）
├── prefs.json        # shared_prefs 全量：笔迹颜色、浏览模式、内置词库标记等
└── pkg/…             # filesDir/qbank_pkg 下的材料配图
```

**一份包 = 一次完整快照**。换台手机恢复，试卷、做过的记录、手写笔迹、背诵掌握进度、配图全都在。

打包前会执行 `PRAGMA wal_checkpoint(TRUNCATE)`：Android 默认开 WAL，只拷主库文件会漏掉还在 `-wal`
里没落盘的作答记录（刚交卷那几秒正是这种情况），所以先把日志合并回主库再读。

## 两种存法

| 存法 | 操作 | 适合 |
|---|---|---|
| 留在本机 | 「立即备份」 | 恢复时手边就有，防误删 |
| 分享出去 | 「立即备份」→ 弹窗里的「分享 / 存到网盘」 | **百度网盘、天翼云盘、微信、邮箱**——系统分享面板里选哪个 App 就存到哪儿 |

分享走 `FileProvider`（authority `com.lytree.qbank.fileprovider`），只放行 `cacheDir/backups/`，
备份包之外的东西一概不暴露给外部 App。

## 为什么没有百度网盘 / 天翼云盘直连

两家的开放平台都不对个人开放：

* **天翼云盘**：能力开放平台把接入方式分成「商务机构开发者 → 基础能力 API」和「个人独立开发者 → 小程序平台」，
  小程序那侧官方写明「目前仅支持企业商户申请入驻，**未面向个人开发者开放**」；
* **百度网盘**：2024 年起调整认证规则，个人开发者认证与个人创建应用的入口已下架，控制台只留企业认证。

没有企业主体就拿不到 AppKey/SecretKey，写 SDK 也是死代码。**非官方接口**（拿 cookie 模拟登录）
违反服务条款、随时失效、还要处理验证码，不做。

所以这两家在这套方案里是「**存文件的位置**」而不是「对接的 API」：备份包用系统分享直接丢进网盘 App，
恢复时从网盘下载到手机、用「从备份文件导入」选它。功能闭环，合规，且不依赖任何审核。

## 备份历史

备份页「备份」卡里的「备份历史」进去是**独立一页**，把每次成功备份列出来：时间、来源（手动 / 自动）、
体积、试卷与题目条数。点一条出动作菜单：**恢复 / 分享 / 删记录**，标题栏右侧「清空」一次清完。

* **为什么单独一页**：备份页已经背着备份 / 恢复 / 导入三段，历史铺进去会把「立即备份」顶到看不见的地方；
  历史要能翻到几十条、要能一条条收拾，卡片里装不下；
* **记录跟文件是两回事**：本地只留 2 份（`LOCAL_KEEP`），包迟早会被清掉，记录照样留着——
  「哪天备过」这件事本身不该跟着文件一起消失；
* **恢复仍走预览**：本机还留着包就直接用；已经被清掉的会明说找不回来——
  想留得住的，备份后点「分享」存进网盘，恢复时从「从备份文件导入」选回来；
* **删记录不删包**：「删除这条记录」只动列表，zip 还在 `cacheDir/backups` 里；
* **不进备份包**：历史存在 `backup_meta` 这个 prefs 里，打包时被 `prefsToJson` 跳过——
  否则从旧包恢复会把历史倒退回备份当时那几条，看起来像刚备过。

最多留 40 条（`BackupHistory.MAX`），单条几十字节，存在 `SharedPreferences` 里。

## 恢复

恢复区**直接把手上能恢复的备份列出来**（本机 `cacheDir/backups` 里现存的包，最多 2 份，新的在前），
点一条就走预览确认；列表末尾一行「从备份文件导入」用系统文件选择器选 zip——从网盘下载下来的那份也走这里。
不再先点一行再弹层挑，少一层点击。

选中之后不会直接覆盖，先**解包校验并弹出预览**：备份时间、试卷/题目/记录条数、配图张数、体积、
来源设备与 App 版本、包里的库版本（低于本机会注明「恢复后自动升级」）。看完点「覆盖并恢复」才动数据，
点「取消」只清掉临时解包目录。校验失败（选错 App 的包、MD5 对不上、来自更新版本）在这一步就报错退出，
不会留下换了一半的库。

落地顺序是「先配图、后换库」，每一步失败都能回滚：

1. `QBankDb.closeInstance()` 放掉数据库句柄（不关的话换过去的库会被旧连接覆盖回来）；
2. `qbank_pkg` 改名成 `.old` → 拷入新配图，失败则把 `.old` 改回去，**此时数据库还没动**；
3. `qbank.db` 改名成 `.before-restore` → 拷入新库 → 删掉旧的 `-wal`/`-shm`
   （不删的话打开新库会把旧日志回放上去）；失败则把 `.before-restore` 改回去，并把配图也回滚；
4. 恢复 `prefs.json`；
5. 全部成功才清掉两份留底。

校验：`manifest.json` 的 `app` 必须是 `qbank`（防止误选别的 App 的包）、`schema` 不能比当前版本新、
`dbMd5` 要和解出来的库对上（传输截断会在这里被抓到）、`dbVersion` 不能高于当前库版本
（高版本拒绝恢复并提示先升级 App，避免丢字段）。

版本兼容（`dbVersion` ↔ `QBankDb.DB_VERSION`）：

| 备份来源 | 新版 App（库 v12） | 改动前的老版 App（库 v11） |
| --- | --- | --- |
| v11 备份 | 可恢复；旧进度串按旧格式读，下次保存自动转新格式 | 可恢复 |
| v12 备份 | 可恢复 | **拒绝**，提示先升级 App |

v12 只改了未交卷进度串（`exam_progress.answers`）的编码，表结构没动，所以 11 → 12 是**空迁移**，
打开旧库不会重建表、也不会清数据。之所以要提这一版，是因为新编码老解析器读不了，
不提版会让老 App 恢复 v12 备份时把进度静默读丢。

恢复完成后会提示重启——各页面还持有旧 id，重启才干净。

## 相关代码

```
data/backup/
├── BackupArchive.kt      # 打包 / 解包 / 校验 / 落地（install），以及 prefs 的 JSON 往返
├── BackupManager.kt      # 编排：打包 → 本地留 2 份；解包校验（openForRestore）→预览→落地（installOpened）
└── BackupHistory.kt      # 备份历史（prefs 里的 JSON 数组，不进备份包）
ui/backup/BackupFragment.kt      # 备份页（备份 / 分享 / 恢复列表 / 导入）
ui/backup/BackupHistoryFragment.kt # 备份历史页
ui/backup/RestoreSession.kt      # 恢复链路（校验 → 预览 → 覆盖），两个页面共用
```

回归测试：`androidTest/BackupArchiveTest.kt` 只测「打包 → 解包 → 校验」，
不动真实数据库（`install` 会把测试机上的库换掉，不适合自动化）。
