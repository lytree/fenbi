# 10 备份与恢复

设置页 → 「备份与恢复」。整库打包成一个 zip，可以留在手机里、分享进任何网盘、或直接传到 WebDAV。

## 备份包里是什么

```
qbank-backup-20261029-2230.zip
├── manifest.json     # 包标记 / 创建时间 / 库版本 / 条数 / 体积 / db 的 MD5
├── qbank.db          # 试卷、题目、作答记录、笔迹、笔记、判题规则（整库一份）
├── prefs.json        # shared_prefs 全量：笔迹颜色、浏览模式、内置词库标记等
└── pkg/…             # filesDir/qbank_pkg 下的材料配图
```

**一份包 = 一次完整快照**。换台手机恢复，试卷、做过的记录、手写笔迹、背诵掌握进度、配图全都在。

打包前会执行 `PRAGMA wal_checkpoint(TRUNCATE)`：Android 默认开 WAL，只拷主库文件会漏掉还在 `-wal`
里没落盘的作答记录（刚交卷那几秒正是这种情况），所以先把日志合并回主库再读。

## 三种存法

| 存法 | 操作 | 适合 |
|---|---|---|
| 留在本机 | 「立即备份」 | 恢复时手边就有，防误删 |
| 分享出去 | 「立即备份」→ 弹窗里的「分享 / 存到网盘」 | **百度网盘、天翼云盘、微信、邮箱**——系统分享面板里选哪个 App 就存到哪儿 |
| WebDAV | 填地址账号 → 「备份到云端」 | 想让它自动跑、又不想每次手动传 |

分享走 `FileProvider`（authority `com.lytree.qbank.fileprovider`），只放行 `cacheDir/backups/`，
备份包之外的东西一概不暴露给外部 App。

## 为什么没有百度网盘 / 天翼云盘直连

两家的开放平台都不对个人开放：

* **天翼云盘**：能力开放平台把接入方式分成「商务机构开发者 → 基础能力 API」和「个人独立开发者 → 小程序平台」，
  小程序那侧官方写明「目前仅支持企业商户申请入驻，**未面向个人开发者开放**」；
* **百度网盘**：2024 年起调整认证规则，个人开发者认证与个人创建应用的入口已下架，控制台只留企业认证。

没有企业主体就拿不到 AppKey/SecretKey，写 SDK 也是死代码。**非官方接口**（拿 cookie 模拟登录）
违反服务条款、随时失效、还要处理验证码，不做。

所以这两家在这套方案里是「**存文件的位置**」而不是「对接的 API」：备份包用系统分享直接丢进网盘 App，
恢复时从网盘下载到手机、用「从备份文件恢复」选它。功能闭环，合规，且不依赖任何审核。

## WebDAV 怎么填

任选一家支持 WebDAV 的：

| 服务 | 地址 | 说明 |
|---|---|---|
| 坚果云 | `https://dav.jianguoyun.com/dav/` | 网页端「账户信息 → 安全选项 → 添加应用密码」，**密码填这个，不是登录密码** |
| Nextcloud | `https://你的域名/remote.php/dav/files/用户名/` | 同上，用应用密码 |
| 群晖 DSM | 控制面板开 WebDAV Server，`https://IP:5006/` | 需要端口可达 |
| InfiniCLOUD | `https://(节点).teracloud.jp/dav/` | 免费 20GB，注册后在设置里生成 WebDAV 密码 |

目录默认 `qbank`，会在首次上传时自动 `MKCOL` 建出来。填完点「测试连接」能立刻知道通不通。

> 用的是 OkHttp 而不是 `HttpURLConnection`：后者对请求方法有硬编码白名单
> （只有 GET/POST/HEAD/OPTIONS/PUT/DELETE/TRACE），发 `PROPFIND` 会抛 `ProtocolException`。

## 自动备份

开关打开后，用 `AlarmManager.setInexactRepeating` 每天 **03:30** 跑一次，把当天的包传上去，
然后按「保留份数」（默认 7 份，可调 3/5/7/10/15/30）删掉最旧的。

* 只在**配好 WebDAV 且开关打开**时才挂闹钟，否则到点什么也不会发生；
* 每次启动 App 重新挂一次（重装、强制停止会清掉闹钟）；
* 失败静默——半夜不该弹窗。备份页的「上次备份」时间没更新，就说明没成。

没上 WorkManager：这个 App 一路零依赖，一天一次、迟到几十分钟无所谓的任务，闹钟足够。

## 恢复

两条入口：**从备份文件恢复**（系统文件选择器选 zip）/ **从云端恢复**（列出 WebDAV 目录里本 App 生成的包）。

落地顺序是「先配图、后换库」，每一步失败都能回滚：

1. `QBankDb.closeInstance()` 放掉数据库句柄（不关的话换过去的库会被旧连接覆盖回来）；
2. `qbank_pkg` 改名成 `.old` → 拷入新配图，失败则把 `.old` 改回去，**此时数据库还没动**；
3. `qbank.db` 改名成 `.before-restore` → 拷入新库 → 删掉旧的 `-wal`/`-shm`
   （不删的话打开新库会把旧日志回放上去）；失败则把 `.before-restore` 改回去，并把配图也回滚；
4. 恢复 `prefs.json`；
5. 全部成功才清掉两份留底。

校验：`manifest.json` 的 `app` 必须是 `qbank`（防止误选别的 App 的包）、`schema` 不能比当前版本新、
`dbMd5` 要和解出来的库对上（传输截断会在这里被抓到）、`dbVersion` 不能高于当前库版本
（高版本拒绝恢复并提示先升级 App，避免丢字段）。

恢复完成后会提示重启——各页面还持有旧 id，重启才干净。

## 相关代码

```
data/backup/
├── BackupArchive.kt      # 打包 / 解包 / 校验 / 落地（install），以及 prefs 的 JSON 往返
├── BackupManager.kt      # 编排：打包→上传→留 N 份；下载→恢复；清理本地缓存
├── CloudProvider.kt      # 云存储接口 + CloudFile 模型 + CloudStore 偏好
├── WebDavProvider.kt     # WebDAV 实现：PROPFIND 列表 / MKCOL 建目录 / PUT / GET / DELETE
├── CloudHttp.kt          # OkHttp 薄封装 + 带进度的请求体
└── AutoBackupScheduler.kt # 每日闹钟 + AutoBackupReceiver
ui/backup/BackupFragment.kt # 备份页
```

回归测试：`androidTest/BackupArchiveTest.kt` 只测「打包 → 解包 → 校验」，
不动真实数据库（`install` 会把测试机上的库换掉，不适合自动化）。
